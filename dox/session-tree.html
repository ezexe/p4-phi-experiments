The session tree

A session in the Claude desktop app is either a top session or a session that another session started. p4-phi hands tasks, notes and reports along those links. Make each move on the tree below, watch the links redraw, and copy the call or command that makes the move for real.

  • The app keeps one record.It is the nesting in the sidebar. It decides which session is told when a turn ends, and which sessions are archived together.
  • phi keeps another.It is spawnedFrom in each session's session.json. It decides who gets a session's background, notes and reports.
  • They can disagree.Some moves change only one record. Switch the view above the tree to see each side, and follow the dashed line to the other side's parent.

    Decided, and not yet in the plugin
    
    
    Two rules are settled and open as issues. The sessions follow them by hand today. Wherever this page describes them, it marks them with this dashed border.
    
    
    
      
    ezexe/p4#48: one writer per file
    
      
      
        
    • There is one work tree, with no git worktree and no branch of a child's own.
      • 
        
    • phi refuses or holds a start whose file set overlaps a live session's file set.
      • 
        
    • Every brief declares its file set, and phi records it on the child's page. A brief with no file set is refused.
      • 
        
    • A leaf is one issue, one file set, one proving test and one commit. A child whose task spans more splits it again.
      • 
        
    • Only the session that started a child changes its queue. Only the tree's top session pushes.
      • 
      
    
    
    
    
    
      
    ezexe/p4#49: ezexe archives
    
      
      
        
    • No session archives another session or itself.
      • 
        
    • phi tells ezexe that a finished session is ready to archive, and only ezexe's own action in the app archives it.
      • 
        
    • The chain does not wait. The parent holds the replaces: note at once, and the tree and the relay treat the session as archived from then.
      • 
        
    • A marked session that is messaged again is named as reopened.
      • 
        
    • Briefs end with "report when done" in place of "archive when done".
      •
